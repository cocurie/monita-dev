## 1. 製品概要

| 項目 | 内容 |
|---|---|
| 用途 | 橋梁などのインフラ構造物に設置する、電池駆動の多チャンネル計測ノード。ひずみ・変位を主対象とし、センサモジュールの差し替えで温度・傾斜・距離にも対応する |
| 位置づけ | Monita シリーズの主力計測機。Monita Gateway（LoRa/BLE 受信 → LTE-M でクラウドへ）の子機になる。Sigfox 版は Gateway なしで直接クラウドへ送る |
| 動作 | 間欠動作。起床 → 計測 → 送信 → ディープスリープ を繰り返す（BLE 版は例外。§4-3） |
| 通信 | Sigfox / LoRa / BLE のうち **1台につき1方式**。製造時のファーム書き込みで決まり、出荷後は変えられない |

### システム構成

```
                ┌───────────────── Monita Flex ─────────────────┐
センサ ─JP─┐   │ Flexモジュール(AFE) ×最大4 → MUX → XIAO nRF52840 │
センサ ─JP─┼──→│ DS3231(RTC・基板温度)  電池 → TPS63900 → 3V3     │
  …        │   │ 無線: Sigfox(BRKLSM100A) / LoRa(E220-900T22S(JP)) / BLE(内蔵) のいずれか
           │   └──────────────────────────────────────────────┘
           │        │Sigfox                 │LoRa / BLE
           │        ▼                       ▼
           │   Sigfox網 → クラウド     Monita Gateway ──LTE-M──→ GAS → スプレッドシート
           │                              ▲ │
           │                              │ └─ LoRa ダウンリンク（設定変更。LoRa 版のみ）
```

## 3. 計測仕様

### 3-1. チャンネル構成

チャンネルごとのセンサ種別はファームの定数 `CH_ASSIGN` で決まる（**ビルド時に固定**。現場や遠隔では変えられない）。出荷時の既定は 4CH すべて HX711（`main.cpp:216`）。

| CH_ASSIGN | センサ | 送信値の単位 | 区分 | 根拠 |
|---|---|---|---|---|
| 1 | HX711 系 Flexモジュール（ひずみ・変位） | 表示µε（整数） | 設計値 | `main.cpp:1611-1632` |
| 2 | LSM6DS3/DSO/DSL 加速度センサ（I²C、アドレス 0x6B）→ ピッチ角 | 度 ×10 | 設計値 | `main.cpp:224`、`:1416-1461` |
| 3 | DS18B20（1-Wire 温度）。外付けプルアップ 4.7kΩ 必須 | ℃ ×10 | 設計値 | `main.cpp:213`、`:920-973` |
| 4 | VL53L4CD（ToF 距離） | mm | 設計値 | `main.cpp:1478-1571` |

- 1台の中で種別を混在できる（CH ごとに指定）。
- ADS1115（電圧）、MCP9601（熱電対）、XIAO Sense 内蔵 IMU・マイクは **v3.20 ファームでは読めない**（§10）。

### 3-4. サンプリング方式（HX711）

2段階のロバスト化を行う（`main.cpp:1151-1199`）。

1. 生サンプル **5 回の平均**を1つ作る（`SAMPLES_PER_AVG`、`main.cpp:245`）
2. これを **5 回**繰り返し、5つの平均値の**中央値（メジアン）**を送信値にする（`MEASURE_COUNT`、`main.cpp:247`）
3. 5つの平均値の最大−最小を「ブレ幅（Range）」として LoRa/BLE で送る（0〜255 表示µε に丸める）

| 項目 | 仕様 | 区分 | 根拠 |
|---|---|---|---|
| 平均回数（初期値） | 5 | 設計値 | `main.cpp:245` |
| メジアン回数（初期値） | 5（上限 20） | 設計値 | `main.cpp:247`、`:252` |
| LoRa ダウンリンクでの変更範囲 | 平均 1〜255、メジアン 1〜20。範囲外は拒否（丸めない） | 設計値 | `main.cpp:2184-2191` |
| 1サンプルの待ち上限 | 1 秒（超えたら断線などのエラー） | 設計値 | `main.cpp:992` |
| HX711 の出力レート（10/80 SPS） | 未確定（モジュール側の RATE 端子設定を確認していない） | 未確定 | — |
| 1回の計測にかかる時間 | 未確定（出力レート次第。10 SPS なら 4CH で約 10 秒の計算） | 未確定 | — |

VL53L4CD は 50 サンプルのメジアンを 50 回取り、その中央値を送る（1 サンプル 100 ms、`main.cpp:257-261`）。**1CH あたり計算上 250 秒以上かかる**ため、電池寿命に大きく影響する。

### 4-3. BLE 版の動作（注意）

v3.20 の BLE ビルドは **常時アドバタイズ設定**（`ADV_CONTINUOUS_MODE 1`、`main.cpp:115`）。スリープせず、約10秒ごとに計測してアドバタイズ内容を更新する（`main.cpp:2667-2669`）。**電池運用には使えない**（AC 電源を確保できる現場向け）。
時間窓方式（20分ごと計測・毎時 0〜2分に10分間アドバタイズ、`main.cpp:109-111`）はコード上にあるが無効。

### 4-4. 遠隔設定（LoRa 版のみ）

## 8. 使用上の制約・注意（顧客に説明すること）

1. **表示µεはクォーターブリッジ換算値。** ハーフブリッジ（ゲージ2枚）では真ひずみの約2倍、フルブリッジでは約4倍を示す。理論値と比べるときは換算する。
2. **温度は基板温度であり、外気温ではない**（DS3231 内蔵センサ、精度 ±3℃）。また LoRa・BLE 版は温度を送信していない。
3. **通信方式は1台につき1つで、出荷後は変えられない。** 遠隔設定は LoRa 版だけ。
4. **OTA はない。** ファーム更新・CH 構成の変更は現地で PC 接続が必要。
5. **Sigfox・BLE 版は時刻を補正できない。** DS3231 のずれはそのまま残る（量は未測定、F-R6）。
6. **センサ異常時の送信が方式で違う。**
   - Sigfox 版: どれか1つでもエラーがあるとそのサイクルは送信しない（`main.cpp:1765`）。**装着していない CH を `CH_ASSIGN` で有効にしたままだと毎回エラーになり、一度も送信されない。**
   - LoRa 版: エラーがあっても送信する（iPEC 疎通試験用の一時的な設定、`main.cpp:2287-2296`）。**異常な CH は 0 として送られ、本当の 0 と区別できない。**
   - 統一方針は未決定（B-3）。
7. **送信周期は時刻に揃わない。** 実周期は「送信間隔＋計測・送信の時間」で、LoRa はさらに ±10 秒ずれる。
8. **BLE 版は常時動作のため電池運用できない**（§4-3）。
9. **LoRa は ACK がない単発送信**（2 回送信で補っているのみ）。多台数での衝突率・欠測率は未測定（F-C5）。
10. **v3.20 基板の電池電圧は正しく測れない恐れがある。** v3.20 で電池分圧回路に追加したスイッチ（Q4、TCA9534 の P7 で駆動）をファームが操作していない（P7 は入力のまま、`main.cpp:829`）。読み値の妥当性は未検証（F-B7、差分v3.20 §D）。
11. ダウンリンクには認証がない（C-X1）。

## 付録A. 送信データ形式（概要）

数値はすべてリトルエンディアン（ダウンリンク・確認応答の 2 バイト値のみビッグエンディアン）。

**Sigfox（12 バイト、`main.cpp:1790-1797`）**

| バイト | 内容 |
|---|---|
| 0-7 | CH1〜CH4（int16 ×4） |
| 8-9 | 基板温度 ℃×10（int16） |
| 10-11 | 電池電圧 mV（int16） |

**LoRa アップリンク（PktType 0x04、`main.cpp:2307-2326`）**
フレーム: `[0xAA][LEN=19][本体19B][チェックサム=(0xAA+LEN+Σ本体)&0xFF]`。受信側 E220 が末尾に RSSI 1 バイトを付ける。

| バイト | 内容 |
|---|---|
| 0 | PktType 0x04 |
| 1 | DEVICE_ID |
| 2 | FW 版 |
| 3-10 | CH1〜CH4（int16 ×4） |
| 11-12 | 電池電圧 mV（uint16） |
| 13-14 | 時・分（DS3231、読めなければ 0） |
| 15-18 | CH1〜CH4 ブレ幅（uint8、0〜255） |

**BLE（Manufacturer Specific Data 21 バイト、`main.cpp:2372-2393`）**: 先頭に Company ID 0xFFFF、PktType 0x03。以降は LoRa 本体の 1〜18 バイト目と同じ並び。デバイス名 `Monita-XX`（XX=DEVICE_ID）。

**LoRa ダウンリンク（Gateway→Flex、PktType 0x81、15 バイト、`main.cpp:2060-2070`）**: Company ID 0xC0DE（2B）/ PktType / DEVICE_ID / フラグ（bit0 時刻・bit1 送信間隔・bit2 平均/メジアン）/ 時刻 6B（年下2桁・月・日・時・分・秒）/ 送信間隔 分（2B）/ 平均回数 / メジアン回数。

**確認応答（Flex→Gateway、PktType 0x05、9 バイト、`main.cpp:2094-2106`）**: PktType / DEVICE_ID / status（0=適用、1=範囲外）/ 適用後の送信間隔（2B）/ 平均回数 / メジアン回数 / WDT タイムアウト 分（2B）。
