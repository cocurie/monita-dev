# gateway_common — Gateway共通GAS受信・リモート制御スクリプト

Monita Gateway（LTE-M/LoRa）から送られてくる子機データの受信・記録に加え、
スプレッドシート発のリモートコマンド（Gateway操作・Flex子機へのLoRaダウンリンク）を
仲介するGoogle Apps Script。

## ★このファイルの位置づけ（重要）

`Code.gs` は **各案件へコピーする「元ファイル（テンプレート）」**である。

- **特定の現場・本番監視に紐づくものではない。**
- 案件ごとに本ファイルをコピーし、それぞれ独立した Apps Script プロジェクト／
  スプレッドシートを立てて運用する。
- 各案件で加えた個別の変更は**その案件のフォルダ側で管理**し、
  現場固有の設定（スプレッドシートID・デバイスID台帳・現場名など）を
  このファイルへ書き戻さないこと。

  ただし **`SPREADSHEET_ID` だけは例外**で、この共通ファイルにも実IDを置く（2026-08-30変更）。
  プレースホルダのままデプロイして「送信成功と表示されるのにシートに何も入らない」状態に
  丸一日ハマったため。定義は `Code.gs` 最上部の警告ブロック内にあり、コピー時は必ず書き換える。

共通で使う機能（受信・記録、LoRaダウンリンクのリモート制御基盤、
Gateway/Flexのバージョン対応表など）を改善した場合のみ、このファイルへ反映する。

## このリポジトリのコードとGASエディタの同期について

GAS本体はGoogle側（スプレッドシート紐付け）で動作しており、`Code.gs` はその
**バックアップ・レビュー用のコピー**。GASエディタで編集した内容は、このファイルにも
手動で反映すること（clasp等の自動同期は未導入）。

## 主な機能

- **子機データ受信**（`doGet()`）: BLE/LoRa経由でGatewayが送ってくるテレメトリをdataboxシートへ記録
- **旧/新クラウド形式の両対応**: 1台26 hex（13B、電池なし）と28 hex（14B、電池あり）を`d.length / n`で判別。不正長は`invalid_payload_log`へ記録して破棄
- **製品種別台帳**: `DEVICE_PRODUCT_REGISTRY`でDeviceIDを製品プロファイルへ結び、CH列名・単位・スケール・欠測・アラート閾値を切り替え
- **計測日時の保持**: 行の日時にはGAS到着時刻ではなく、Gatewayレコード内のepochを使用
- **電池電圧**: 新形式の末尾1バイトを`3000 + value * 5`mVで復元し、Q列へV単位で記録。`255`と旧形式は空欄
- **Gateway遠隔操作**（スプレッドシート「Gateway操作」メニュー）: リモートリセット、データ送信の停止/再開、送信間隔変更、ステータス確認、RTC再同期、診断ログ吸い上げ
- **Flex子機へのLoRaダウンリンク**（スプレッドシート「Flex操作」メニュー）: 送信間隔・平均/メジアン回数の変更を、Class A方式（子機のアップリンク直後の受信窓に便乗）＋確認応答（子機からの適用結果を受けて完了とする）で配信
- **`cmd_status`シート**: Gateway・子機の現在の予約状況・MAC・状態・結果を一覧表示。DeviceIDは上位3bitをGateway群、下位5bitを機器番号（1〜31）に使い、現在の許可範囲は群0=`0x01`〜`0x1F`。案件側の`CMD_STATUS_CHILD_IDS`に登録したIDを対象とする
- **群別ダウンリンク**: `check_cmd?dl=1&group=N`に対し、DeviceIDの上位3bit
  （`childId >> 5`）が群Nと一致する予約だけを返す。group未指定の旧Gatewayは群0扱い
- **ACK所有権検証**: `downlink_sent` / `downlink_result`の報告群と子機IDの群を比較し、
  不一致は予約を更新せずログへ記録
- **`downlink_log`シート**: ダウンリンクの予約・送信・結果（期限切れ・群不一致を含む）とGateway群を1イベントごとに履歴として記録

## LoRaダウンリンクのアーキテクチャ

子機は省電力のためアップリンク送信直後の短い時間（実装上は2秒）しか受信できない。
そのためGatewayは:

1. 数十秒おきにGASの `action=check_cmd&dl=1&group=N` を叩き、自群の未完了予約をローカルキャッシュする
2. LoRaを常時受信し、子機のアップリンクを検知した瞬間にキャッシュを照合し、
   一定の応答遅延（実装上は400ms、子機の受信窓が開くタイミングに合わせる）を置いて
   ネットワークを介さず即座にダウンリンクを送る
3. 送信しただけでは予約を消さない。子機からの確認応答フレームを受けて初めて完了とし、
   結果をGASへ報告する。規定回数(3回)送っても確認が返らなければ「未達」として打ち切る

タイミング設計の詳細な経緯（なぜ即座に応答すると失敗するか等）は、
社内メモリ `lora_downlink_class_a_timing` を参照。

## バージョン対応

`Code.gs` 冒頭のコメントに、GASスクリプトのバージョンと対応する
子機ファーム・Gatewayファームのバージョン対応表を記載している。
ペイロード形式を変更した場合は、双方のコミット時にバージョンを+1し、
このREADMEおよびCode.gs冒頭のコメントも更新すること。

## 案件へコピーした後の必須設定

1. `SPREADSHEET_ID`のプレースホルダを対象シートIDへ置き換える。
2. `DEVICE_PRODUCT_REGISTRY`へ、その案件で使うDeviceIDと製品プロファイルの対応を定義する。
3. 必要な製品種別を`PRODUCT_PROFILES`へ追加し、CH1〜4の列名・単位・スケール・欠測値・アラート条件を定義する。
4. `CMD_STATUS_CHILD_IDS`を実際の子機一覧に合わせ、通知を使う場合は`ADMIN_MAILS`を設定する。

`gateway_common`自体には、実スプレッドシートID、現場名、案件固有のDeviceID台帳を置かない。
