## このリポジトリのコードとGASエディタの同期について

GAS本体はGoogle側（スプレッドシート紐付け）で動作しており、`Code.gs` はその
**バックアップ・レビュー用のコピー**。GASエディタで編集した内容は、このファイルにも
手動で反映すること（clasp等の自動同期は未導入）。

## 主な機能

- **子機データ受信**（`doGet()`）: BLE/LoRa経由でGatewayが送ってくるテレメトリをdataboxシートへ記録
- **Gateway遠隔操作**（スプレッドシート「Gateway操作」メニュー）: リモートリセット、データ送信の停止/再開、送信間隔変更、ステータス確認、RTC再同期、診断ログ吸い上げ
- **Flex子機へのLoRaダウンリンク**（スプレッドシート「Flex操作」メニュー）: 送信間隔・平均/メジアン回数の変更を、Class A方式（子機のアップリンク直後の受信窓に便乗）＋確認応答（子機からの適用結果を受けて完了とする）で配信
- **`cmd_status`シート**: Gateway・Flex子機（0x01〜0x0E）それぞれの現在の予約状況・MAC・状態・結果を一覧表示。予約・消化のたびに自動更新
- **`downlink_log`シート**: ダウンリンクの予約・送信・結果（期限切れも含む）を1イベントごとに履歴として記録

## LoRaダウンリンクのアーキテクチャ

子機は省電力のためアップリンク送信直後の短い時間（実装上は2秒）しか受信できない。
そのためGatewayは:

1. 数十秒おきにGASの `action=check_downlinks` を叩き、未完了の予約をローカルキャッシュする
2. LoRaを常時受信し、子機のアップリンクを検知した瞬間にキャッシュを照合し、
   一定の応答遅延（実装上は400ms、子機の受信窓が開くタイミングに合わせる）を置いて
   ネットワークを介さず即座にダウンリンクを送る
3. 送信しただけでは予約を消さない。子機からの確認応答フレームを受けて初めて完了とし、
   結果をGASへ報告する。規定回数(3回)送っても確認が返らなければ「未達」として打ち切る

タイミング設計の詳細な経緯（なぜ即座に応答すると失敗するか等）は、
社内メモリ `lora_downlink_class_a_timing` を参照。

## バージョン対応

`Code.gs` 冒頭のコメントに、GASスクリプトのバージョンと対応する
子機ファーム・Gatewayファームのバージョン対応表を記載している。
ペイロード形式を変更した場合は、双方のコミット時にバージョンを+1し、
このREADMEおよびCode.gs冒頭のコメントも更新すること。
