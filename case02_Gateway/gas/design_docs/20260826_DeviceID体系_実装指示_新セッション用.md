## 1. 背景（要約）

株式会社コクリエの橋梁モニタリング製品。

- **Monita Flex**（子機・電池・XIAO nRF52840）：Sigfox / BLE / LoRa をビルド時排他で選択
- **Monita One**（子機・ソーラー・XIAO nRF52840）：LoRa / Sigfox
- **Monita Gateway**（AC電源・XIAO nRF52840 + SIM7080G）：子機からBLE/LoRaで受信しLTE-MでGASへ送信

**課題**：1つの現場に Gateway 2台、各Gatewayに最大31台の子機という構成を予定しているが、
現在は全機が同一のE220設定で通信し、Gatewayの受信フィルタはDeviceIDホワイトリスト（`0x01`〜`0x0F`）のみ。
**2台のGatewayが同じ子機を二重受信してしまう。**

**解決策**：DeviceIDを **上位3bit=Gateway群（0〜7）／下位5bit=機器番号（1〜31）** に分割する。
無線層（E220のチャネル）は変更しない。電波法対応のコストを避けるためソフトフィルタ方式を選択した。

```
DEVICE_ID (1バイト)
  上位3bit = Gateway群 (0〜7)    → group   = deviceId >> 5
  下位5bit = 機器番号 (1〜31)     → localNo = deviceId & 0x1F   ※0は無効値
```

**群の境界**：群0 = `0x01`〜`0x1F`、群1 = `0x21`〜`0x3F`、群N の開始は `N × 0x20 + 1`。

**既存機器への影響なし**：現在稼働中の `0x01`〜`0x0F` はすべて群0に収まる。焼き直し不要。

## 3. 実装内容

### A. Gateway（`case02_Gateway/firmware/gateway_v1.20/`）

#### A-1. `GW_DEVICE_ID` をXIAO固有IDから生成する

現状 `src/main.cpp:1076` は固定文字列です。

```c
static char const* GW_DEVICE_ID = "gateway_v11_test";
```

2台のGatewayが同じIDでGASに接続すると、リモートコマンド予約の取得競合、status_report・log_dumpの
混在が起きます。**これはDeviceIDの群分離では解決しない、独立した識別問題です。**

**XIAO固有ID（`NRF_FICR->DEVICEID`、64bit）から `gw_<16桁hex>` を生成してください。**
取得関数は `src/main.cpp:2806-2812` 付近に実装済みです（info行の `xiao=<ID>` として送信もしている）。
まず既存実装を確認してください。

**必須要件**

- **固定長のグローバル `char` 配列**（例 `static char GW_DEVICE_ID[24];`）に `snprintf` で生成する
- **一時的な `String` の `c_str()` を保持してはいけません**（関数終了後にポインタが無効になる）
- **`checkRemoteCmd()` が最初に呼ばれる前に必ず初期化**すること（`setup()` の早い段階）
- 既存の使用箇所（`:1117` status_report、`:1163` log_dump、`:1446` check_cmd、`:1483` ack_cmd）が
  そのまま動くこと。`char const*` → `char[]` の変更で型エラーが出ないか確認

#### A-2. `GATEWAY_GROUP_ID` の導入

```c
#ifndef GATEWAY_GROUP_ID
#define GATEWAY_GROUP_ID 0
#endif
static_assert(GATEWAY_GROUP_ID >= 0 && GATEWAY_GROUP_ID <= 0x07,
              "GATEWAY_GROUP_ID must be 0..7");
```

#### A-3. LoRa専用の受信判定関数を新設する（★最重要）

現在の `isAllowedFlexPacket()`（`src/main.cpp:236` 付近）は **BLEとLoRaの共通関数**です。
これを群方式に置き換えると**BLEも群分離されてしまいます**。

**BLEの群分離は今回のスコープ外**（LoRaへの移行が進むため後回しと決定）なので、
**LoRa専用の関数を新設し、BLE用の既存関数はそのまま残してください。**

```c
// 新設（LoRa用）
static bool isAllowedLoRaPacket(uint8_t pktType, uint8_t deviceId) {
  if (pktType != EXPECTED_PKT_TYPE) return false;   // 既存の定数名に合わせること
  if ((deviceId & 0x1F) == 0) return false;         // 下位5bit 0は無効値
  return (deviceId >> 5) == GATEWAY_GROUP_ID;       // 上位3bitが群一致
}
```

**変更箇所**

- LoRa受信経路（`src/main.cpp:2283-2300` 付近）：`isAllowedFlexPacket()` → `isAllowedLoRaPacket()`
- **BLE受信経路（`src/main.cpp:1685-1701` 付近）は変更しない**
- 既存の `ALLOWED_DEVICE_IDS[]`（`:226`）と `isAllowedFlexPacket()` は**BLE用として残す**

#### A-4. 配列サイズの拡張

| 定数 | 現在 | 変更後 | 場所 |
|---|---|---|---|
| `MAX_PENDING_CHILDREN` | 15 | **31** | `:1191` |
| `MAX_DEVICES` | 20 | **32** | `:259` |

RAM増分は約1.6KB（実測：現在7.8% = 18,608B / 237,568B → 約8.5%見込み）。
コメントの「子機DeviceID 0x01〜0x0F」等も「当該群の下位番号1〜31」に更新してください。

#### A-5. ダウンリンク予約取込時の群検証

`applyDownlinkCache()`（`src/main.cpp:1361-1386` 付近）は現在 `childId == 0` しか検証していません。
GASが全Gatewayに同じ予約一覧を返すため、**他群の予約が `s_pending[]` を占有します**。

**群が一致しない childId を除外してください**（既存の値域チェックに条件を追加する形で可）。

#### A-6. 群1以上ではダウンリンクを無効化

第1段階ではGAS側の群別配信が未実装のため、**`GATEWAY_GROUP_ID != 0` のときはダウンリンク機能を
無効化**してください（予約の取得・送信・ACK処理をスキップ）。
シリアルログに「群Nのためダウンリンク無効」の旨を起動時に1回出力すること。

> **補足**：ダウンリンクは現在すべてテスト段階で現場実装がないため、この制約による実害はありません。

#### A-7. 起動ログとinfo行

- 起動時のシリアルログに `GW_DEVICE_ID`、`GATEWAY_GROUP_ID`、XIAO固有ID を出力
- info行（`src/main.cpp:2829-2856` 付近）に `GW_DEVICE_ID` と群番号を追加
  **※ URL 512バイト制限（`SHREQ_MAX_URL_BYTES`）に注意。既存の長さ計算を壊さないこと**

#### A-8. その他

- `platformio.ini` に `GATEWAY_GROUP_ID` の指定方法をコメントで記載
  例：`PLATFORMIO_BUILD_FLAGS="-D GATEWAY_GROUP_ID=1" pio run -t upload`
- `README.md` の `0x01〜0x0F` 固定という記述（88-93行付近）を新体系に更新
- **`GATEWAY_FW_VERSION` を +1**（社内ルール。現在値を確認して1つ上げる）

### B. Monita Flex（`case01_Flex/v3.20/`）

#### B-1. `DEVICE_ID` をビルド時上書き可能にする

現在 `src/main.cpp` の2箇所でC++定数として定義されています。

- `:102`（`#ifdef COMM_MODE_BLE` ブロック内）：`static const uint8_t DEVICE_ID = 0x01;`
- `:120`（`#ifdef COMM_MODE_LORA` ブロック内）：`static const uint8_t DEVICE_ID = 0x0E;`

**両方をマクロ方式に変更**してください（既定値は現状維持）。

```c
#ifndef DEVICE_ID
#define DEVICE_ID 0x0E      // LoRaモードの場合。BLEモードは 0x01
#endif
```

**使用箇所**：`:1978, :2048, :2086, :2258, :2305, :2325, :2355, :2451` 付近。
`msd[1] = DEVICE_ID;`、`Serial.print(DEVICE_ID, HEX)`、`snprintf(bleName, ..., DEVICE_ID)` 等。
**マクロ化で問題が出ないか必ず確認**してください。

#### B-2. 静的検証

```c
static_assert((DEVICE_ID) >= 0x01 && (DEVICE_ID) <= 0xFF,
              "DEVICE_ID must be 0x01..0xFF");
static_assert(((DEVICE_ID) & 0x1F) != 0,
              "DEVICE_ID low 5 bits must be 1..31 (0 is reserved)");
```

#### B-3. 起動ログ

完全DeviceID・群番号（`>> 5`）・群内番号（`& 0x1F`）を出力してください。

#### B-4. その他

- **`FW_VERSION` を +1**（**モードごとに別定数**なので、変更したモードの定数を上げること。CLAUDE.md §6）
- `platformio.ini` に機体別ビルドの手順をコメントで記載
