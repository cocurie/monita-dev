## S2 で確認すること（基板が届いたら上から順に）

| # | 確認内容 | 失敗したときに見るところ |
|---|---|---|
| 1 | TCA9534 が応答する | I²C プルアップ R26/R27（4.7 kΩ）、アドレス A0-A2=GND |
| 2 | CLKIN(D2) に 8.000 MHz が出る | オシロで直接。PWM0 の設定 |
| 3 | ADS131M06 が ID=0x26xx を返す | CLKIN が先に出ているか、SYNC/RESET(P3) が High か、DVDD（FL1 の先）の電圧 |
| 4 | 全レジスタのリードバックが一致 | SPI モード1（CPOL=0/CPHA=1）、CS の遷移が SCLK Low 中か |
| 5 | **実効SPSが設計値（1295.3）どおり** | ★GC 有効時は `fCLKIN/(2×OSR)` ではない。上の「データレート」参照 |
| 6 | CRC エラー 0 / **欠測 0** | SCLK 8 MHz、DRDY 割込み、SPI 配線長 |
| **7** | **起動ログに「入力CRCを無効にして起動」の警告が出ていない** | 下の「入力CRC」参照 |

### ★ 入力CRC（F-2）

`Config::rxCrcEn` は **既定 true**。フレーム構成はデータシートで確認済みである。

```
通常コマンド : [語0]コマンド  [語1]CRC(語0を計算)      [語2-7]ゼロ
単一WREG     : [語0]コマンド  [語1]書く値  [語2]CRC(語0+語1を計算)
```

**★フレーム末尾（語7）ではない。**2026-09-12 の実装は語7に置き、先頭21バイトを
対象にしていた（外部レビュー指摘）。SBAS949A §8.5.1.7 の
"the command, the command CRC ... and six additional words of zeros" と
§8.5.1.10.8 の "write this CRC after the register data" が根拠。

**ここを間違えると切り分けが難しい壊れ方をする。**RREG などは実行されなくなる一方、
**WREG だけは誤ったCRCでも書き込まれる**とデータシートに明記があるため、
「書けているのに読めない」という症状になる。

**初期化に失敗した場合、`begin()` が自動で入力CRCを切って一度だけ再試行する。**
それで通ったときは起動ログに★の警告枠が出て `crcFallback()` が true になる。
**この警告が出たら、原因は配線でも CLKIN でもなく入力CRCの形式である。**
計測自体は続くが F-2 を満たしていないので、放置しないこと。

**シリアルに1秒ごとの統計と6CHの生コード／µV を出す。**

```
1295.0 SPS（設計 1295.3）  総 12950  CRC異常 0
  欠測 0 サンプル / 中断 0 回 / FIFO吐き出し 0 回  STATUS異常 0
  リング番号 12950  検出 0/収録 0  EVQ溢れ 0
```

### ★ 欠測の数え方（STATUS の DRDY ビットでは数えられない）

出力FIFOはCHあたり**2段**あり、データシート §8.5.1.9.1 に
*"The DRDY flag ... remains set until **both** samples for each channel are read"*
とある。**1つ読み落としても STATUS は 0x3F のまま**なので、ここを見ても欠測は分からない。
（2026-09-12 の実装は `drdy != 0x3F` を欠測として数えており、機能していなかった）

実際に効くのは**読み出し間隔**である。1.5周期を超えたぶんを欠測として数え、
`Frame::gapBefore` で呼び出し側へ返す。**呼び出し側はそのぶんリングの番号を進めること**
（`SampleRing::pushGap`）。詰めて格納するとサンプル番号が時刻を表さなくなる。

### ★ 中断した後は FIFO を吐き出させる

FIFOが2段とも埋まると、以後のDRDYの挙動が不定になる。データシートは
「SYNC/RESET を叩く」か「**2フレームを素早く読む**」を要求している。
本機の SYNC/RESET は I²Cエキスパンダの先にあり ISR から叩けないので後者を使う。
`readFrame()` が中断を検知すると、次の読み出しの先頭で自動的に1フレーム捨てる。

**SD書込みなどで意図的に読み出しを飛ばしたときは `notifyPaused()` を呼ぶこと。**
呼ばないとDRDYが不定になり、原因の分かりにくい停止につながる。

## 設計上の注意（実装で踏みやすい箇所）

### ★ EXTREF_EN を必ず立てる

本機は **REFIN = VEX/2 = 1.25 V の外部リファレンス**でレシオメトリック測定をする。
CLOCK レジスタの `EXTREF_EN`（bit6）を 1 にしないと内蔵 1.2 V が使われ、
**VEX のドリフトが相殺されなくなる**。設計の根幹が静かに失われるので、
`verifyRegisters()` のリードバック照合を必ず通すこと。

REFIN の規格は 1.1 / **1.25 typ** / 1.3 V（SBAS949A 表7-3）。VEX/2 はちょうど typ にあたる。

### ★ 1 LSB の式

要件定義 F-7 の `LSB = (2.4/Gain)/2^24` は**内蔵基準（1.2 V）の式**。
**FSR = ±0.96 × VREF / Gain**（要件定義 §3.3 の表）なので `LSB = (2 × 0.96 × VREF / Gain)/2^24`。
外部基準 1.25 V では **`LSB = (2.4/Gain)/2^24`**、ゲイン32 で **1 LSB = 4.470 nV、FSR = ±37.5 mV**。

> ★2026-09-12、ここを一度「2.5/Gain・4.657 nV・±39.06 mV」と書き換えたが**誤りだった**
> （係数 0.96 を落としていた。4.17% のゲイン誤差になる）。外部レビューの指摘で戻した。
> 0.96 × 1.25 = 1.2 なので、外部基準 1.25 V でも FSR は内蔵基準と同じ ±1.2 V/Gain になる。

`ADS131M06::lsbVolts()` は外部基準 1.25 V を既定にしてある。

### ★ データレートに `fCLKIN / (2 × OSR)` を使わないこと

**その式はグローバルチョップ（GC）が無効のときにしか成り立たない。**本機は GC 必須なので、

```
fDATA = 1 / (tGC_DLY + 3 × OSR × tMOD)        （SBAS949A 式8）
      = 4.000 MHz / (16 + 3 × 1024) = 1295.34 SPS
```

GC は入力極性を入れ替えるたびにデジタルフィルタをリセットし、**1つの確定値を出すのに
内部変換を3回行う**ため、ざっと 1/3 になる。OSR 4096 のままだと 325 SPS しか出ない。

**2026-09-12 の実装は 976.56 SPS 前提で全定数を組んでいた**（外部レビューで発覚）。
OSR を 1024 に変更し、1295.34 SPS・サンプル間隔 **0.772 ms** で確定した（要件 §4.1a）。

- 値は `ADS131M06::dataRateSps(cfg)` が設定から計算する。**数字を手で書き写さないこと。**
- 起動時に `DeckMeasure::F_DATA_SPS` と突き合わせ、ずれていれば警告を出す
- 保存フォーマットに実データレートを記録すること（要件 §5.4）
- **RESET 直後の1本目だけは変換時間が約2倍**になる（SBAS949A 式9）。DRDY 間隔で驚かないこと

### ★ 起動順序

- **TCA9534**（F-25）：出力レジスタ 0xAA → 方向レジスタ 0xA0 の順。逆にすると P0 が一瞬 High になり VEX が入る
- **ADC**（F-26）：CS を High → CLKIN 開始 → SYNC/RESET を 256 µs 以上 Low → レジスタ設定
- **E220**（F-27）：M0/M1 を Low → `Serial1.end()` して TX を Low 固定 → Q1 OFF → 待機 → Q1 ON
  （TX のアイドル High と M0/M1 から逆給電され、電源を切ってもリセットされないため）

### ★ SPI バス共有（F-28）— S6 を書く前に必ず読むこと

ADC（モード1）と microSD（モード0）が**同じバス**（D8/D9/D10）にいる。CS だけ別。
どちらも CPOL=0 なので SCLK のアイドルは Low で共通。切替時は
「両 CS High → SD 後は 8 クロックのダミー → `SPISettings` 切替 → 対象 CS を Low」。

**`SPI.beginTransaction()` は排他ロックではない。**SD の転送中に DRDY 割込みが入って
CS_ADC を落とすと CS が2本とも Low になり、**両方の転送が壊れる**。
これを防ぐのが `lib/SpiBus`。

```cpp
// main 側（SDなど）
{
  spibus::Lock lk;                      // ← スコープを抜けると自動で離す
  digitalWrite(PIN_CS_SD, LOW);
  ... 512 バイト転送 ...
  digitalWrite(PIN_CS_SD, HIGH);
}                                        // ← 待っていた DRDY がここで処理される

// ISR 側（実装済み）
if (spibus::busyFromIsr()) { ring.pushGap(1); adc.notifyPaused(); return; }
```

**★1ブロック（512 B）ごとに握り直すこと。**イベント波形は 117 kB あり、一度に握ると
0.3〜0.5 秒バスを占有して**その間のサンプルが全部欠測**になる。
**★SD の内部ビジー中は握らないこと。**ビジーは数 ms〜数百 ms ありうる。
ブロックを送り終えたら CS_SD を上げて Lock を離し、ビジー確認のたびに握り直す。

起動後の統計に `最長保持 xxx µs` が出る。**1周期（772 µs）を超えていたら、
その回数だけ確実に欠測が出ている。**ブロック単位に割れているか確認すること。

## メモリ配分の見通し

| 用途 | サイズ |
|---|---|
| リングバッファ 6秒（7,770サンプル）× 6CH × 3B packed | 140 kB |
| 現状のスケッチ（実測） | 9.5 kB |
| SD 書込みバッファ（4 kB × 2、S6 で追加予定） | 8 kB |
| **計** | **約 158 kB** / 237.5 kB |

**イベント切出し用の 117 kB コピーは持たない。** リング6秒に対し切出しは最大5秒なので、
発火後はリングから直接 SD へストリーミングし、1秒の余裕で追い越しを防ぐ。
`int32_t[7770][6]` にすると 186 kB になり成立しない（要件 §7.3.3・Codexレビュー指摘）。

**★プリ＋ポストの合計は 5.0 秒以下。**`TriggerConfig::fitsInRing()` が受理前に検査し、
GAS 側（`deckRowToTrigBytes_`）も同じ検査をする。**片方だけ直さないこと。**
