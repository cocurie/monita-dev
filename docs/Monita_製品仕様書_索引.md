## 数値の区分

| 区分 | 意味 | 営業資料に載せてよいか |
|---|---|---|
| 実測 | 測った値。日付・条件・記録の場所を書く | 載せてよい |
| データシート | 部品メーカーの公称値。部品と資料名を書く | 載せてよい |
| 設計値 | ファームの定数や回路で決まる値。ファイルと行を書く | 載せてよい |
| 目標値 | 要件定義の値で、まだ確かめていない（Deck など開発中の製品のみ） | 原則載せない。載せるなら「開発目標」と明記 |
| 未確定 | 決まっていない・測っていない | **載せない** |

## 更新の流れ

1. 仕様が変わったら（ファーム・基板の変更、実測の追加、未確定の確定）、**先に仕様書を直す**。営業資料を先に直さない。
2. 仕様書の `spec_version` を上げ、`updated` と「改版履歴」に何を変えたかを書く。
3. 営業資料などへ転記するときは、転記先に「出典: Monita ○○ 仕様書 v△」と書いておく。どの版から写したかが分からなくなるのを防ぐため。
4. 同じ数値を仕様書の中で2か所に書かない。別の章で使うときは参照にする。

## いま直すべき既存資料

各仕様書の「既存資料との相違」の表に、現行の営業資料（`【7】Monita/01_開発/Monita_製品性能まとめ_営業資料用.md`、2026-08-11 版）や設計資料と食い違う点をまとめてある。営業資料を使う前に、その表を見て直すこと。
